# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository layout

MultimodalPhysioKit is a research toolkit for offline and window-based processing of synchronized physiological signals (ECG, EDA, respiration, skin temperature, fNIRS). It ships **two parallel implementations** of the same API:

- `python/` — the `multimodalphysiokit` package (src layout, `python/src/multimodalphysiokit/`), published to PyPI. `pyproject.toml` lives in `python/`, not the repo root.
- `matlab/` — the `mpk` package (`matlab/+mpk/`) with object-facing classes over the older procedural per-modality functions in `matlab/{ecg,eda,fnirs,respiration,temperature,utils}/`.

Numerical changes to one implementation usually need matching changes in the other; cross-language parity is validated via `examples/cross_language_validation/`.

## Commands

Install for development (from the repo root):

```bash
python -m pip install -e "python[test]"            # add ,examples for notebooks
```

Python tests (`testpaths = ["tests"]`, so run from `python/` or pass the path):

```bash
cd python && python -m pytest -v
python -m pytest python/tests -v                     # from repo root, as CI does
python -m pytest python/tests/test_recording.py::test_name -v
```

MATLAB tests (from repo root; needs Signal Processing + Statistics and ML toolboxes):

```matlab
run('matlab/tests/run_matlab_tests.m')
```

Other CI checks (`.github/workflows/python-ci.yml`):


## Architecture

Data flow: input adapter → `Signal` → modality processor → `ProcessingResult`.

- **`Signal`** (`core/signal.py`): samples, strictly increasing time vector, positive sampling frequency, label, units, metadata. Can represent a full channel, an extracted phase, or a completed real-time window — processors never know its origin.
- **Processors** (`processors/*.py`): each modality exposes a configured class (`ECGProcessor`, …) with a `process(*signals, **kwargs)` method plus a functional wrapper (`process_ecg`, …). Processors receive only the supplied `Signal`(s) — never a `Recording` or phase definitions. fNIRS takes a synchronized pair (red, infrared). Processing may be noncausal (e.g. `filtfilt`); processors are not sample-by-sample streaming implementations.
- **`ProcessingResult`** (`core/processing_result.py`): `features` holds only final scalars; `metadata` is concise scalar/descriptive info; arrays and diagnostics go in `intermediates` (populated when `return_intermediates=True`).
- **`Recording`** (`core/recording.py`): optional container of named signals (each with its own sampling frequency/length) plus shared phase intervals. `process_signal` / `process_phases` duck-type any object with a callable `.process`. `process_phases` returns `dict[phase_label, ProcessingResult]`; feature names stay phase-independent. Each phase is extracted then processed independently, so boundary effects differ from filter-then-slice — this is intended.
- **I/O** (`io/`): `recording_from_arrays`, `read_generic_hdf5` (explicit dataset mappings and exactly one timing source; never infers schemas), and `read_biosignalsplux_hdf5` (assigns canonical names like `ecg`, `eda`, `rip`, `temp`, `fnirs_red`, `fnirs_infrared`). The library does not synchronize or resample streams.

### Phase semantics (easy to get wrong)

- Phases are specified in **seconds**, stored as a `(2, n_phases)` array: row 0 starts, row 1 ends, half-open `[start, end)`. Labels must be nonempty and unique; overlap is allowed.
- Python maps seconds to zero-based indexes via `numpy.searchsorted` on each signal's own `time`. MATLAB `mpk.Recording` uses the same seconds/half-open semantics, but procedural MATLAB functions use one-based inclusive indexes internally — convert carefully when comparing across languages.

### EDA / cvxEDA

EDA requires the official, unmodified external cvxEDA v1.1.0 (`pip install cvxeda==1.1.0`, or MATLAB `cvxEDA.m` on the path). There is deliberately **no fallback** decomposition. `EDAProcessor` resolves an installed module, a `cvxeda_path`, or a `decomposition_callable`; tests inject fakes via `decomposition_callable` (Python) or `matlab/tests/helpers/fake_cvxeda.m`. Keep `external/cvxEDA.m` untracked.

## Project rules

- Public tests must use synthetic data only. Never commit recordings, private paths, participant identifiers, `validation-output/`, or `local_validation/` (see `docs/local_validation.md`). The tracked `examples/sample_data/synthetic_multimodal_180s.hdf5` is generated by `tools/generate_synthetic_sample.py`; regenerate it with that script rather than editing it.
- Keep metadata free of large arrays and sensitive information.
- When bumping the version, update `python/pyproject.toml`, `CITATION.cff`, and `CHANGELOG.md` together. `__version__` is read from installed package metadata.
- Changes to scientific methods, public APIs, or dependencies should be discussed before implementation and documented in `docs/` (modality pages in `docs/modalities/`) and the changelog.

## Working rules
- Python lives in a virtual environment at .venv. Activate it with
  `source .venv/bin/activate`, or call `.venv/bin/python` directly.
  Never use --break-system-packages.
- Run `python -m pytest python/tests -q` after every change; never leave tests failing.
- Fix one issue per commit, with a regression test that fails before the fix.
  Tests should check against physical or reference ground truth where possible,
  not copy the implementation's formula.
- Do not push, merge, or switch branches unless asked.
- Any change that alters feature values must be noted in CHANGELOG.md.
- When fixing a numerical bug in Python, check whether the MATLAB implementation
  has the same bug and report it before changing MATLAB.
